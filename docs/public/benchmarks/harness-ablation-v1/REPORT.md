## 2. 分模块实验设计说明与面试应答要点

### 2.1 `StuckDetector v2`（为什么 HYN 在 SWE-bench 上实现 100/100 零空补丁？）
- **痛点**：在 SWE-bench Verified Mini 对照实验中，官方 `mini-SWE-agent` 在 `django-11848` 与 `sphinx-8548` 上因陷入重复探索耗尽 80 步上限，产出空补丁。
- **实证**：HYN 的 `StuckDetector` 同时监控 **D1 连续精确重复、D2 12步滑动窗口重复、D3 周期 T=2/3 乒乓振荡、D4 同错误指纹重复、D5 25步无进展空转、D6 文本复读**，按 `L1 告警 → L2 强制无工具复盘 (complete_without_tools) → L3 签名封禁 → L4 优雅收尾` 四级阶梯收敛，在 18 组死循环测试中达成 **100.0% 检出率** 与 **-87.7% 步数节省**，且在 6 组正常分页读取与 TDD 迭代轨迹上保持 **0.0% 误报**。

### 2.2 `ContextCompactor`（如何在压缩 81.6% 超长输出的同时，不丢报错行号且不打碎 KV Cache？）
- **痛点**：测试或构建失败的日志往往长达数万字符，传统头部截断（`output[:4000]`）会 100% 截丢位于末尾的 Python Traceback 和 AssertionError（基线保留率仅 `33.3%`）；同时如果每步立即去重历史 `read_file`，会直接修改已进入服务端缓存的早期 Message，导致 Prefix Cache 整段失效。
- **实证**：HYN 采用 **60% 开头（保留导入与执行命令）+ 40% 结尾（保留异常堆栈与退出码）** 保真预览，在压缩 **`93.1%`** 字符体积的同时实现 **`100.0%`** 关键事实锚点保留；配合 **75% 窗口水位延迟去重公式**，将意外缓存断裂从 25 次降至 **0 次**。

### 2.3 `Multi-Agent Git Worktree`（多智能体并行如何做到零文件覆盖与零 Git 污染？）
- **实证**：4 名常驻队友各自通过 `ContextVar` 绑定独立的 `.hyn_wt/mate-*` 分离头指针工作树（`git worktree add --detach`），即使 4 名队友在同一毫秒修改同名共享文件 `shared_registry.json`，文件冲突率仍为 **0.0%**，取得 **`2.88×`** 实测墙钟加速比；配合 `git commit-tree` 写入私有引用 `refs/hyn/checkpoints/`，用户主工作区 `HEAD` 与 `.git/index` 实现 **100% 零污染**。

### 2.4 `PermissionGate`（桌面端 Agent 如何抵御间接 Prompt Injection 越权？）
- **实证**：三道权限门（物理硬拒绝 `command_hard_deny_reason` + 路径越界沙箱 `_path_escapes` + 受保护目录 `.hyn_agent`/`.env` 门禁）对 30 组破坏性命令与越界补丁实现 **100.0% 拦截（攻击成功率 ASR = 0.0%）**；同时通过 AST/词法位置识别（区分命令行首的 `shutdown` 与 `git commit -m "fix shutdown"` 或 `Get-Date -Format`），在 30 组正常研发命令上实现 **0.0% 误报**。
