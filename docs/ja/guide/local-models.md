# Ollama・社内LANモデル設定

日本企業の開発現場において最も重視される **「情報セキュリティ（ソースコードや設計書の外部送信禁止）」** に対応するため、HYN Agent はモデルカタログ（`app/catalog/models.py`）レベルで `local`（端末内オフライン）、`lan`（社内イントラネット）、`cloud`（クラウド）の3区分をネイティブサポートしています。

## 1. ローカル Ollama への接続（完全オフライン稼働）

### Ollama の起動とモデル取得
ローカルPCで [Ollama](https://ollama.com/) を起動し、コーディング向けモデルを取得します：
```powershell
ollama pull qwen2.5-coder:14b
# または 32GB 以上のメモリ搭載機では：
ollama pull qwen2.5-coder:32b
```

### HYN Agent でのワンクリック有効化
1. **「設定 → モデル」** を開き、**「Ollama（ローカルオフライン）」** を選択します。
2. デフォルトのエンドポイント `http://127.0.0.1:11434/v1` が設定済みであり、**APIキーの入力は不要**（`requires_key=False`）です。
3. カスタムモデルID（例：`qwen2.5-coder:14b`）を追加して接続テスト（Probe）を実行すれば、LANケーブルを抜いた状態でも全機能が稼働します。

---

## 2. 社内LANプライベートLLM（vLLM / SGLang / OneAPI）への接続

社内のGPUサーバー上で運用されている **vLLM**、**SGLang**、**Xinference**、**OneAPI** などの OpenAI 互換エンドポイントへ直結できます。
1. **「設定 → モデル」** から **「社内LANモデル（企業内ネットワーク）」**（`id: lan_server`）を選択します。
2. ベースURLに社内サーバーのアドレス（例：`http://192.168.1.100:8000/v1`）を入力します。
3. 社内トークン（任意）とモデルIDを設定することで、**ソースコードを一切社外に出すことなく、チーム全体で高性能な社内GPUクラスタを活用**できます。

---

## 3. ローカル中規模モデル向けの安定化エンジニアリング

7B〜32Bクラスのローカルモデルは、クラウドの超大規模モデルに比べてツール呼び出し（Tool Calling）のループや途中終了が起きやすい課題があります。HYN Agent は以下の3層でこれをカバーしています：
1. **`TurnHub` + `stream_reset`**：生成途中のエラー再試行時に、フロントエンドの不完全なストリーム表示を自動破棄して整合性を維持。
2. **`StuckDetector` L1/L2 内省注入**：同じエラーを出すコマンドの繰り返しを検知し、`L2_RETROSPECTIVE_NOTICE` を自動注入して別アプローチへ誘導。
3. **明示的完了プロトコル（`completion.py`）**：テスト未検証のまま早期終了することを防止。
